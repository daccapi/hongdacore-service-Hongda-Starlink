# 版本迭代与归档规范

仓库目录版本：1.0.1（2026-09-06，增加 Windows 1.6.26 / Core 1.10.13）；首次归档为 1.0.0。软件版本随实际修复迭代。

| 对象 | 规则 | 当前基线 |
| --- | --- | --- |
| Windows App | pubspec 的应用版本与构建号；Release tag 为 windows-v版本 | 1.6.26+186 |
| Service | 与 Core 嵌入关系单独记录，不冒充 App 版本 | 1.5.13 |
| Windows Core | Core CLI/API 版本；Release tag 为 core-v版本 | 1.10.13 |
| Android App | 独立迭代；修订 R3–R9 保留原名；tag 为 android-v版本-修订 | 1.6.5+165 / R9 |

1. 修复/新增功能先更新对应代码、测试与 CHANGELOG，再修改对应产品版本号。
2. 同一版本的 Source.zip、程序包与 SHA256SUMS.txt 绑定，禁止覆盖旧附件制造同名不同内容。
3. GitHub tag 指向该组件相应源码快照；Git 自动源码包不含预编译组件，原始完整历史包见 Source.zip。
4. 历史快照导入日期为本次归档时间，不伪造为原始开发提交时间；快照不是虚构的完整开发历史。
5. 已知问题版写明风险，不用“最新版”标识覆盖警告。1.9.0-rc.1 等候选版本保持预发布属性。
6. 修改分流、DNS、TUN 或协议时先做隔离测试；真实联网测试与普通构建结果分开描述。
7. 更新 releases/index.json 和三个分类目录；程序包通过 Releases 上传，不进入普通 Git 树。

缺少某个历史版本的原始包时只记录缺失，不用邻近版本重命名补数。
