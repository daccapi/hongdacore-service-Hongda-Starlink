# V1.6.22 DPAPI、DNS 缓存与 URLTest 更新

版本链：鸿达星轨智连 `1.6.22+182` → HongdaService `1.5.9` → HongdaCore `1.10.9`。

## 本地敏感数据

- Windows Flutter Runner 使用 `CryptProtectData/CryptUnprotectData`，范围为当前用户。
- 设置、节点和订阅文件整体加密，原子备份同样是密文，不保留明文 `.bak`。
- 应用内存和连接期间的运行配置仍必须短暂包含节点认证信息；运行配置沿用 V1.6.21
  的断开清理机制。

第一次启动会迁移旧明文文件。密文与当前 Windows 用户及计算机绑定，复制到其它账户
或电脑不能直接解密；V1.6.21 也不能读取新格式。需要回退时应使用首次运行前保留的
`%APPDATA%\HongdaStarlink` 副本。

## DNS TTL 持久化

- 只保存 Core 已验证可缓存且 TTL 未过期的 DNS wire response。
- 写入周期为五秒，Core 关闭时补充刷新；不会为每次 DNS 查询同步写盘。
- Windows 缓存使用 DPAPI；过期、损坏、版本不匹配和其它用户密文直接忽略。
- 保持 V1.6.20 的 4096 条上限及最大十分钟 TTL，不制造长期陈旧解析。

## URLTest

- 当前节点健康且与最优节点差值小于等于 tolerance：保持当前节点。
- 最优节点的优势超过 tolerance：切换最优节点。
- 当前节点失败而有其它成功节点：立即故障转移。
- 所有节点失败：保留最后选择并标记不健康，不伪报切换成功。

## 验证边界

- Flutter 静态分析、存储迁移测试和 Windows 原生构建。
- Core 普通/`with_gvisor` 测试、`go vet`、DPAPI 缓存及 URLTest 单元测试。
- 不自动运行 Hongda TUN，以避免和当前 Karing TUN 冲突。
