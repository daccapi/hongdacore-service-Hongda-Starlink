# V1.6.25 稳定性修复记录

日期：2026-09-05。应用 1.6.25+185 / Service 1.5.12 / Core 1.10.12。

## 范围与网络保护

从 V1.6.24 建立独立源码目录；原版本目录和 ZIP 保留。只修复审查确认的缺陷，
不修改用户订阅、系统代理、物理网卡、Karing 或系统 TUN 路由。

## 主要修复与对应源码

| 问题 | 修复 | 源码位置 |
| --- | --- | --- |
| WS 丢失 continuation 帧、握手不响应超时 | 正确处理分片、控制帧及帧长度；握手限定在调用 context 内 | Core protocol/transport_ws.go |
| gRPC 空包死锁/崩溃、重复 TCP/TLS 建连 | 循环跳过空数据，校验消息长度，一次完成 ALPN 与建链 | Core protocol/transport_grpc.go、transport.go |
| QUIC 缓存会话终止后无法重建 | 检查连接 context，清理失效会话，并发 TCP 请求共享一次握手 | Core protocol/hysteria2.go、tuic.go |
| 切换节点仍复用旧 DoH 出口 | 节点感知连接池；Selector/清理连接取消旧 DNS 请求 | Core route/dns.go、api/controller.go |
| DNS 失败隐式回退系统解析、缓存时间延长 | 加密解析失败返回错误；尊重 TTL 0/短 TTL、回复老化、SOA/OPT 区分、缓存作用域隔离 | Core route/router.go、dns.go、dns_persistence.go |
| 恶意 DNS 压缩指针循环 | 迭代解析、循环与边界检测，限制跳转与域名长度 | Core route/dns.go |
| HTTP 503 被测速算成功，大量探针竞争带宽 | 手动/自动统一 HEAD、禁止重定向、仅 2xx；全局并发 4，固定组工作池 | Core probe/url.go、strategy/urltest.go |
| 自动选到端口开放但代理不工作的节点 | 只选 proxyAvailable 且有完整代理探针的节点，按完整探针排序 | lib/src/node_health.dart、app.dart |
| HY2/TUIC 的延迟与状态被 TCP 测速误导 | 跳过无关 TCP 测试，使用真实 QUIC 代理探针 | lib/src/singbox_controller.dart |
| TUN HTTPS 失败后被单纯路由成功覆盖 | 失败后每个周期继续 HTTPS 复核；巡检结果带连接代次隔离 | lib/src/tun_watchdog_health.dart |
| 未选中损坏节点阻止启动 | 校验 UUID、密码、服务器、端口及出站类型；隔离无效节点 | lib/src/singbox_config_builder.dart |

DNS 持久化格式升级到内部版本 2，旧缓存自动忽略后重新解析；不删除用户文件。
本次没有取消 TLS 验证，也没有通过修改延迟数字掩盖代理失败。

## 源码与构建

应用：本目录；核心/TUN 适配：相邻 hongda-core 或源码包 third_party/hongda-core。
执行 tools/build-release.ps1 构建 Windows，tools/package-source.ps1 制作带 Core 的源码 ZIP。
Core 的 TUN 使用 sing-tun、gVisor、Wintun 第三方组件，不能称为全部原创。

测试新版本时应由用户自行决定何时停止其他 TUN 客户端，不要让两个 TUN 同时接管路由。
