# Hongda Starlink V1.6.4 Window/VLESS/172 Bugfix

基于 V1.6.3 Bugfix 源码。

## 本次实际修改

- 连接中允许切换手动 VLESS 节点：Clash API 热切换后读取 selector `now` 校验；运行配置不含目标节点时自动重载 Core。
- Core 启动/重载后再次同步当前选中节点，避免 `cache_file` 记住旧 selector 导致 UI 与真实出站不一致。
- 节点列表与仪表盘显示“旗帜 + 国家/地区”，并支持按国家/地区搜索；识别不到时显示“未知地区”。
- 普通窗口响应式布局：更早折叠侧栏、降低页边距和卡片高度，工具栏/网络工具/配置页在窄宽度自动换行，减少必须最大化和横向滚动的问题。
- 修复 TUN `172.19.0.0/30` 整段提前 reject：DNS 劫持规则前置，并仅拦截合成 peer `172.19.0.2/32`（IPv6 对应 `fdfe:dcba:9876::2/128`），避免 DNS/下载路径被误杀。
- 按用户要求，本次 **未修改仪表盘中间右侧“实时流量”卡片的数据采集逻辑**。

## 验证

- Go Service：执行 `go test ./...`、Windows 目标 `GOOS=windows GOARCH=amd64 go test ./...` 与 `go vet ./...`。
- Flutter SDK 在当前构建环境不可用，因此未在本环境执行 `flutter analyze/build windows`；源码已进行差异与结构检查。

## CompileFix (2026-08-13)

- 修复 `_SidebarConnectionCard` 误声明未初始化 `dense` 字段导致的构造错误。
- 为 `_ConnectionHeroCard` 正确声明 `final bool dense`，与构造参数和响应式布局使用保持一致。
- 移除运行时 `gap` 变量前错误的 `const SizedBox(...)`，修复 Dart `Not a constant expression` 编译错误。
- 本次 CompileFix 不修改仪表盘实时流量采集逻辑。
