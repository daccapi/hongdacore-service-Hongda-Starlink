# V1.6.26 网络等待与连接清理修复

应用 1.6.26+186 / Service 1.5.13 / Core 1.10.13。日期：2026-09-06。

针对同节点网页慢、YouTube 卡顿的反馈，修复三处可在本地复现的缺陷：

1. TUN HTTPS 连接已经有目标 IP。旧版识别 SNI 域名后丢失用于分流的目标 IP，检查内网/IPv6/IP 规则时又进行 DoH 查询，增加等待，还可能根据另一条 CDN 地址分流。新版将域名与原始 IP 一起用于规则匹配，保留规则顺序；仅有域名的系统代理请求仍按原配置解析。
2. UDP/443 拒绝规则原本在建立流之后执行，关闭流没有通知浏览器，QUIC 会出现重试等待。新版在 sing-tun 的 JudgeFlow 阶段返回 ActionReject，由 gVisor 发出 ICMP unreachable，帮助浏览器尽早回退 TCP。DNS 劫持、LAN 优先和其他 UDP 规则保持原顺序；实际浏览器回退时间由浏览器决定。
3. 双向转发丢弃 io.Copy 的错误，一端读写出错后反方向可能永久等待。新版发生转发错误时关闭两侧连接，回收连接记录和协程。正常 EOF 仍按原半关闭逻辑处理。

关键代码：Core route/router.go、tunnel/handler_windows.go。
回归测试：route/performance_1626_test.go、tunnel/handler_performance_test.go。

验证：修复前已复现已知 IP 分流失效、UDP 错误放行和转发错误悬挂；修复后测试通过。Core with_gvisor 全套本地测试与 go vet 通过。测试仅使用回环 HTTP/DNS、内存连接和规则判断，没有使用真实节点、启动 TUN 或修改系统网络设置。

这是可确认缺陷的修复，尚未证明已消除用户现场的全部卡顿。没有降低 TLS 校验强度、修改节点参数、全局改变 MTU 或关闭 DNS 保护。实际 YouTube 吞吐和卡顿需要用户在相同节点、相同模式下对比。

构建：tools/build-release.ps1；源码打包：tools/package-source.ps1。源码包包含 third_party/hongda-core 对应版本。
