# 鸿达星轨智连 V1.6.3 Bugfix

基于 V1.6.2 Responsive Dashboard 的稳定性修订。

## P0 修复

1. **Service 错误链**：低层 phase 已上报的错误不再被 `main()` 二次包装成泛化 `phase=service`；Flutter 同时按 phase 具体程度选择错误。
2. **Core 生命周期**：HongdaService 将 sing-box 子进程加入 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` Windows Job Object；启动失败时 Flutter 先请求 IPC `stop`，再按超时策略强制结束。
3. **空规则组引用**：仅实际生成成功、包含有效节点的 group 才能作为 `route.final` 或规则 outbound，其他情况回退 `proxy`。
4. **系统代理恢复**：启用代理前持久化原 Windows 代理快照；异常退出后的下一次启动可安全恢复，并通过 ManagedServer 精确匹配避免覆盖用户后来手工修改的代理。
5. **窗口响应式**：Dashboard 不再将固定 1280px 画布整体缩小，改为 >=1120、>=760、<760 三档重排；Windows 最小尺寸改为 760×520。

## 兼容与可靠性

- Sing-box selector/urltest 和 Clash select/url-test/fallback 导入时递归解析嵌套组成员，带循环保护。
- 导入规则可保留具体节点目标 `node:<id>`，配置生成时解析成实际 node tag。
- Sing-box 导入额外保留 `route.final`；Clash 规则正确识别 `no-resolve` 等尾部修饰符，不再把最后一个 token 错当策略组。
- 节点 fingerprint 使用完整 canonical outbound，降低不同 TLS/Reality/transport 配置被误合并。
- 未启动 Core 时的 TCP connect 只作为端口可达诊断，不再写入代理 latency。
- JSON 保存串行化；写入保留 `.bak`，读取可从 `.bak` / `.tmp` 恢复。
- CMake Service build dependencies 增加 Job Object 源文件。
