## Windows gomobile environment regression fix

- Fixed `panic: malformed env var "=::=::\\" from input` when building `HongdaCore.aar` from `cmd.exe` / PowerShell on Windows.
- The Hongda core builder now removes only Windows hidden drive-current-directory pseudo variables (environment entries beginning with `=`) before launching SagerNet gomobile v0.1.12.
- Normal Android SDK/NDK, Java, Go, PATH and user environment variables are preserved.
- The NDK 28.2 vs 28.0 message remains a reproducibility warning and is not the cause of this panic.

## AAR validation fix

- Fixed Windows build validation falsely reporting `Libbox.class missing` after a successful gomobile build.
- `Libbox.class` is stored inside the AAR's nested `classes.jar`; validation now extracts and inspects that JAR.
- Native `jni/*/libhongdacore.so` validation remains enabled.
