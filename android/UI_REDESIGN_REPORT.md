# V1.6 UI / 启动链 Bugfix 报告

## 视觉方向

当前界面以用户提供的浅色 Windows 参考图为准，不再使用早期深色侧栏方案：

- 浅色一体侧栏；
- 无单独顶部标题栏；
- 右上角悬浮最小化 / 最大化 / 关闭；
- 首页大连接卡 + 4 个指标卡；
- 节点列表 + 实时流量 + 快捷操作；
- 底部订阅 / 连接设置 / 系统状态；
- 页面切换、hover、连接、测速、开关均保留动画。

## 本轮代码修正

1. **修复实际编译缺项**：补齐 `_StartupProgress`、`_ServiceFailureDialog`、`_PremiumSwitch` 三个此前被调用但未定义的 Widget。
2. **启动动画**：连接时展示阶段文本、百分比、动画进度条以及 Service / 配置 / Core / API / IPC 五个检查点。
3. **失败交互**：统一动画错误弹窗，展示失败阶段与详细原因，支持“查看日志 / 重新尝试”。
4. **节点测速**：测速中的 spinner 与结果使用 AnimatedSwitcher；紧凑窗口使用独立节点卡片，不再硬塞完整表格列。
5. **普通窗口响应式**：节点工具栏改为 Wrap + 分行搜索/操作，窄窗口不再因为“测试全部 / 添加节点”按钮导致横向溢出。
6. **侧栏贴近参考图**：取消浮动深色/卡片式外框，改为浅色固定侧栏和细右边界；主导航不再显示额外“服务状态”。
7. **主内容留白**：桌面宽屏顶部留出约 72 px 空间，使第一张主卡与参考图位置更接近；紧凑模式约 54 px。

## Service UI 联动

启动页现在会明确呈现：

```text
检查服务组件
→ 验证 Service 版本
→ 检查系统权限
→ 检查本地端口
→ 生成运行配置
→ 校验 sing-box 配置
→ 启动 HongdaService
→ 等待 Core
→ 等待 Clash API
→ 建立 Service IPC
→ 应用系统代理
→ 连接完成
```

这条链的目标是：用户点一次连接，要么进入“已连接”，要么得到明确可定位的失败阶段。
